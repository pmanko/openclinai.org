ChartSearchAI

Answer paths and their evaluation

ChartSearchAI can answer a clinician’s question about a patient chart with its own built-in pipeline, or it can pass the question to Med Agent Hub. This page explains how the two approaches differ, how our evaluations configure them so that the comparison is fair, and which differences in the results reflect genuine differences in capability.

Inspect published evaluations →

Architecture

When ChartSearchAI answers a question with its built-in pipeline, it retrieves the patient’s records, writes a single prompt for a language model, sends that prompt once, applies its drug-safety checks to the reply and returns an answer that cites the records it used.

When ChartSearchAI uses Med Agent Hub, it passes the question to the Hub and displays the Hub’s response. The Hub retrieves the records itself, may call the model several times and checks the answer before and after it is shown. ChartSearchAI’s own answer pipeline is not involved.

In both cases OpenMRS controls which users may ask about which patients, keeps the conversation history and records which path produced each answer.

Model hosting

Where the built-in pipeline’s language model runs is a separate setting from which path answers. By default, ChartSearchAI starts the model inside the OpenMRS server; the recommended model is Gemma 4 E4B, a file of about 5 GB. A site can instead direct ChartSearchAI to a separate model server. This changes only where the single model call is sent. The answer is still produced by ChartSearchAI’s own pipeline.

ChartSearchAI’s Docker installation runs the model on the computer’s processor, because, as its documentation notes, Docker cannot use a graphics chip, even on a Mac. Its macOS installation runs natively and uses the Mac’s graphics chip.

Evaluation configuration

ChartSearchAI runs with its default settings, as an OpenMRS site receives it, including sending the whole patient chart with every question. The only setting we change is the location of its language model.

Both paths use the same language model on the same model server, which runs on a computer with a graphics chip, so neither path benefits from a stronger model or faster hardware.

Every request that either path sends to the model is recorded, so that we can verify exactly what information each path gave the model.

Because the model runs on a shared server, these evaluations do not test how ChartSearchAI starts, sizes, warms and stops its own model inside OpenMRS. Testing that requires a separate run of the installation as shipped.

Capability differences

With both paths on their shipped settings, the following differences remain. They reflect what each path is able to do, not how we configured it.

CapabilityBuilt-in ChartSearchAI pipelineMed Agent Hub
Awareness of the current dateThe prompt does not state the current date, so questions about upcoming visits or the past year depend on the model inferring it.The model receives the current date and each chart date’s distance from it.
Checking dates in the answerDates in the answer are not checked against the chart.Dates in the answer are checked against the chart’s dated records; an incorrect date is corrected or marked.
Checking that citations support the answerThis check is available but turned off by default.Each cited record is checked, and an unsupported citation is labelled.
Clinical guideline sourcesNo guideline sources are available to the model.The Hub can cite records of WHO guidance from its knowledge base.
Drug-safety checksDrug-safety checks are applied.Drug-safety checks are applied.
Second review and supporting detailNeither is available.The checked configuration adds a second model review and an “In Depth” section, and labels its findings rather than hiding them.

Scoring and limitations

Each evaluation asks both paths the same questions and conversations about three HIV patient charts. A separate AI reviewer, working from a fixed scoring guide, scores every answer against the chart for accuracy, completeness, relevance and potential harm.

When the same answers have been scored twice, the averages have moved by up to about 0.6 points, so small differences between the paths should not be treated as meaningful. These are research findings, not product certifications, and every AI-generated answer requires review by a clinician.
