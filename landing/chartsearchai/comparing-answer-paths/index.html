ChartSearchAI

Comparing answer paths

Two ways to answer a chart question, compared fairly.

ChartSearchAI can answer a clinician’s question itself or hand it to Med Agent Hub. We compare the two on the same model and the same charts, with ChartSearchAI set up the way an OpenMRS site gets it, so a difference in the results reflects what each path can do rather than how we configured it.

Two answer paths

01

ChartSearchAI on its own

ChartSearchAI reads the chart, writes the prompt, asks a language model once, runs its drug-safety checks and turns the reply into an answer with links to the records it used.

02

Through Med Agent Hub

ChartSearchAI passes the question to Med Agent Hub and shows what comes back. The Hub reads the chart itself, can call the model several times and checks the answer before and after it is shown.

03

The same safeguards around both

Either way, OpenMRS decides who may ask about which patient, keeps the conversation and records which path answered.

Where the model runs is a separate choice

ChartSearchAI on its own normally starts the language model inside the OpenMRS server, a Gemma 4 E4B model of about 5 GB. A site can instead point it at a separate model server. That changes where the one model call goes, not who builds the answer: the answer is still ChartSearchAI’s own.

In ChartSearchAI’s Docker installation the model runs on the computer’s processor; the README notes that Docker cannot use a graphics chip, even on a Mac. Its macOS installation uses the Mac’s graphics chip directly.

How we keep the comparison fair

Shipped settings

ChartSearchAI runs on its own default settings, including the whole chart in every prompt. Only the location of its model changes.

One model for both

Both paths call the same model on one model server with access to the graphics chip, so neither gets a stronger model.

Every request recorded

Every model request either path sends is recorded, so we can check exactly what each was given.

Running the model on a shared server means our comparisons do not exercise how ChartSearchAI starts, sizes, warms and stops its own model inside OpenMRS; that needs a separate check on the shipped setup.

Reading the results

What a comparison can and cannot tell you

Each evaluation asks the same questions and conversations of both paths on three HIV patient charts, and a separate AI reviewer, working from a fixed scoring guide, scores every answer against the chart for accuracy, completeness, relevance and possible harm.

Scoring the same answers twice has moved averages by up to about 0.6 points, so small differences are not meaningful. These are research findings, not product certifications, and every AI answer still needs a clinician’s review.
