Validation Harness

Repeatable clinical AI and LLM evaluation.

A modular evaluation runner built on one shared provenance, streaming-telemetry and report spine. Run reproducible experiments across point-of-care EHR chart assistants (ChartSearchAI), iterative SQL and cohort analytics (Catalyst), multi-source FHIR R4 summarization (WA Health Summary), or any OpenAI-compatible model or agent endpoint.

How the validation architecture works

01

Measure the live stream and stage milestones

Drive each target’s real interface—OpenMRS SSE streams, Catalyst notebook turns, WAHS condensation calls, or OpenAI SSE completions—and timestamp every frame as it arrives. Time to First Token (TTFT), main answer completion (answer_done), and post-answer review or In-Depth completion (turn_done) are recorded separately rather than collapsed into one wall-clock number.

02

Isolate model capability from runtime artifacts

Use wire-level capture (engine-tap) and explicit transport modes to separate underlying model quality from application-layer prompt assembly, reference-date anchoring, SQL retry loops, or sampler rules (such as conditional DRY repetition penalties on long patient charts).

03

Stress-test multi-session concurrency and goodput

Run N=1, 2, 4+ simultaneous sessions—isolated across distinct OpenMRS clinical accounts or parallel API workers—so concurrent turns do not preempt one another’s conversation state. Report Service-Level Objective (SLO) goodput alongside p50/p95 latency and prefix-cache hit ratios.

What each run records: quality, grounding and streaming telemetry

Evaluating clinical and analytical AI requires both domain correctness (whether the output is faithful to patient records, database state, or privacy rules) and interactive responsiveness (how quickly a user sees the first token and completed answer). Every harness run captures five standardized layers:

Workload and hardware sizing guide

Deployment sizing depends on the prompt context length per turn and number of concurrent active sessions (N). Condensed WA Health Summary views (1k–4k tokens) and Catalyst SQL generation turns require modest prefill compute, whereas ChartSearchAI with fullChart enabled on a longitudinal HIV record sends roughly 12,200 input tokens per turn.
