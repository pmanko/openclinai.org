WA Health Summary · Architecture & Builder Reference

WA Health Summary system architecture

WA Health Summary stores patient records in HAPI FHIR R4, authorizes every read through a per-user proxy (fhir-auth), and routes question answering through wahs-engine, a stateless OpenAI-compatible Python service. Client applications (the web app, mobile companion, and public Research Sandbox) handle presentation and session state while delegating FHIR extraction, condensation, enrichment, prompt assembly, and citation mapping to the engine. Design rationale for condensation, context engineering, and model selection is covered under LLM Strategy.

Repositories: pmanko/wahs-engine ↗ · pmanko/shl-ips ↗ · pmanko/wahs-mobile-frontend ↗ · pmanko/openclinai.org ↗

Core system properties

  1. Per-user FHIR authorization. wahs-engine holds no HAPI database or administrative credentials. It forwards the caller's Keycloak bearer token to fhir-auth (uwcirg/jwt-proxy) on every request, aborts startup if configured against fhir-internal, and strips any resource whose subject does not match the authorized patient.
  2. Stateless request handling. Conversation history stays in the client and is passed as an OpenAI messages[] array on each turn. The engine writes no chat transcripts to disk or database; in-memory dataset and prefix caches are partitioned by verified user subject, dataset timestamps, and request scope.
  3. Deterministic context preparation. FHIR extraction, three-tier structural condensation, and optional enrichment modules execute in deterministic Python before a single southbound /v1/chat/completions call.
  4. Structured citation provenance. Inline [N], [P], and [K] tags map through x_wahs.citation_map to source FHIR resources, unsaved client overlays, and public reference snippets. The final response carries an HL7 AI-Provenance record with human_review_required: true.

Part 1 · System

Services and network boundaries

The hosted stack runs under Docker Compose behind a Caddy reverse proxy with two Docker networks: wahs-net (internal, carrying all patient FHIR and database traffic) and openclinai-edge (connecting services reachable from Caddy). wahs-sandbox-engine attaches only to openclinai-edge and has no route to HAPI FHIR, Keycloak, or PostgreSQL.

Request Pipeline

Five-stage pipeline in wahs-engine

Both POST /v1/chat/completions and POST /v1/wahs/context/preview run Stages 1 through 4; chat completions then execute Stage 5.

Patient-data runtime

wahs-engine

  • Attached only to wahs-net; reads FHIR via http://fhir-auth:8080/fhir using the caller's bearer token.
  • WAHS_ALLOW_LOCAL_BUNDLE_MODE=false and WAHS_DEMO_BUNDLES_DIR unset; inline bundles are rejected and demo routes return 404.
  • Reachable only from the web and mobile BFFs over internal Docker DNS.
Sandbox runtime

wahs-sandbox-engine

  • Same container image on openclinai-edge only, with WAHS_FHIR_AUTH_BASE_URL set to an unroutable placeholder.
  • Mounts ten synthetic and de-identified FHIR R4 bundles read-only at /bundles and accepts JSON bundle uploads (Caddy caps request bodies at 25 MB).
  • Bundle listing and /v1/wahs/context/preview are public; /v1/chat/completions requires the project allowlist cookie (unless the user connects a local model from the browser).

Request Trace

End-to-end request trace

Trace for synthetic patient Margaret Chen (records from Pacific Northwest Geriatrics, Overlake Sleep & Behavioral Clinic, Community Pharmacy, and the WA State immunization registry) asking in the mobile companion: "What active medications am I taking, and are there any fall or sedation risks I should ask my doctor about?"

Step Execution Output / header
1. Client & BFF The mobile app posts to its BFF (POST /api/chat). The BFF strips any browser-supplied fhir_bundle and forwards Authorization: Bearer <keycloak_jwt>, messages[], and wahs options to POST /v1/chat/completions on wahs-engine. OpenAI chat request with wahs options.
2. Assembly assembler.py resolves MasterPatient by JWT sub, reads linked datasets via paged Patient/{id}/$everything, skips re-fetching datasets whose meta.lastUpdated matches cache, applies chart_scope, and runs enforce_single_patient_scope. x_wahs.scope_applied, dataset cache counters.
3. Condensation wahs_core parses FHIR resources, drops entered-in-error and cancelled entries, SHA-256 deduplicates identical notes, and checks token count against the 16,384-token chart budget. Margaret's chart fits at Tier 0. tier: 0, omitted_clinical_items: 0, X-WAHS-Prefix-Hash.
4. Enrichment Under core-enriched, temporal adds date anchors and lab deltas and terminology_kb resolves RxNorm/ATC drug classes (including overlapping sedatives and statins). note_rag and overflow_lookup return empty because Tier 0 excerpted and omitted nothing. x_wahs.enrichers disclosures and token counts.
5. Generation upstream.py yields an initial context_ready SSE chunk carrying citation_map, posts to the southbound model with num_ctx=65536, emits : keepalive comments every 15s while waiting on prefill, and strips <think> blocks from streamed deltas. OpenAI SSE delta chunks (or structured 502 error frame).
6. Provenance The final SSE chunk attaches x_wahs and ai_provenance. The client renders inline [N], [P], and [K] tags as buttons that open the cited entry's resource type, date, and source organization. x_wahs.citation_map and x_wahs.ai_provenance.

Data Model

FHIR dataset layout

Each account has one MasterPatient resource keyed by Keycloak subject (identifier.system = http://keycloak.cirg.uw.edu). Imported clinical sources and patient-authored records are stored as separate linked datasets: each dataset has its own Patient resource referenced from MasterPatient.link[], tagged with category, method, and display name metadata.

Category tag Resources stored Write path
provider-health-recordImported clinic, hospital, pharmacy, and immunization registry bundles.Web import flows (such as SMART on FHIR) and the synthetic persona seeder.
patient-storyJournal notes (Observation, LOINC 51855-5), goals (Goal), care needs (Condition), and discrepancy flags (Flag) with ISO-8601 dates.Web app and mobile companion; each save posts a replacement transaction bundle and updates MasterPatient.link[].
about-me / patient-medical-historyDemographics, occupation (LOINC 11341-5), self-reported conditions, medications, and advance directives.Onboarding and Add Info forms in both apps.

Replacing or updating a dataset advances its Patient.meta.lastUpdated timestamp, which invalidates only that dataset's entry in wahs-engine on the next request.

State & Caching

Identity, session state, and caching

Layer Owner Scope and eviction
Identity & authorization Keycloak, fhir-auth Bearer JWT passed from client BFF to wahs-engine to fhir-auth. enforce_single_patient_scope strips any resource referencing a patient outside the authorized MasterPatient and its linked dataset IDs.
Conversation turns Browser memory Passed in messages[] on every request. When prior turns would push the prompt past WAHS_CONTEXT_WINDOW minus reserved output tokens, the oldest turns are dropped and counted in history_trimmed_turns.
Dataset & prefix caches wahs-engine RAM Dataset cache keyed by (verified_sub, dataset_id, lastUpdated) (default cap: 256 entries / 256 MB). Prefix cache keyed by (verified_sub, datasets_fingerprint, scope_hash, tokenizer_family, prompt_sha256, budget) (default cap: 128 entries / 128 MB), plus TTL eviction.
Model KV cache Southbound GPU host Fixed num_ctx keeps one KV-cache allocation warm across budget presets so unchanged system prefixes avoid full prefill recomputation on follow-up turns.

Packages, condensation tiers, and citation namespaces

Condensation tiers

condense_bundle_to_budget measures candidate outputs with the target model's offline tokenizer and selects the lowest tier that fits budget_effective. Design trade-offs are discussed under LLM Strategy: Condensation.

Tier Activation Mechanics
Tier 0 · VerbatimFull extracted chart fits budget.Drops entered-in-error, cancelled, and unperformed entries, SHA-256 deduplicates identical decoded notes, and emits every clinical item and full note text verbatim.
Tier 1 · Uniform RLE foldingTier 0 exceeds budget.Preserves the HL7 IPS safety core, acute encounters, active care plans, imaging, and full clinical notes verbatim. Run-length folds repeated historical observations, panels, immunizations, historical medications, resolved conditions, procedures, and routine visits sharing a (section, code, unit/status) key into the latest entry plus count, date span, numeric min..max range, and merged memberUuids.
Tier 2 · IPS core & note horizonTier 1 exceeds budget.Reserves the HL7 IPS safety core (patient header, active allergies, active conditions, active medications, active devices, and folded immunizations), binary-searches a monotonic section-interleaved recency prefix, and binary-searches a character horizon across included notes to fill remaining tokens.

Chart numbering and citation namespaces

Marker Target Prompt location & registration
[1], [2], [3]..[N][1] is the patient demographics line; [2] is the Completeness Manifest (tier, included counts, folded/excerpted/omitted counts); [3]..[N] are chart entries, continued sequentially by note_rag and overflow_lookup.Chart in Region 1; recovered passages and items in Region 2. Mapped in x_wahs.citation_map with memberIds when folded.
[P1]..[PM]Unsaved client draft notes and discrepancy flags passed in wahs.overlay_resources (capped at 5,120 bytes).Appended after the chart inside Region 1 (sys_prompt) and added to citation_map.
[K1]..[KM]Public clinical reference snippets matched to chart codes.Appended to Region 2 when guideline_kb is active and added to citation_map.

The default prompt (prompts/wahs-default.txt) enforces numeric/tag-only bracket citations, requires checking [2] before reporting an item absent, requires copying values, units, and ISO dates verbatim without single-point trend extrapolation, and prohibits medication-change directives.

Enricher Runtime

Enricher modules and profiles

Enrichers implement ContextEnricher (wahs_core/ports.py). EnricherPipeline imports wahs_extensions lazily only when active IDs are non-empty, enforces per-module token caps within WAHS_MAX_ENRICHMENT_TOKENS (2,048), appends blocks strictly to Region 2, and records an EnrichmentDisclosure (including fired, tokens_used, and latency_ms) for every module.

Token Accounting

Token accounting and upstream context allocation

wahs-engine separates three token parameters: target chart budget (wahs.target_budget_tokens), physical prompt ceiling (WAHS_CONTEXT_WINDOW), and Ollama KV-cache allocation (WAHS_OLLAMA_NUM_CTX).

  • Offline exact tokenizers: tokenizers_registry.py bundles the Gemma 4 SentencePiece tokenizer.json and pre-cached OpenAI tiktoken encodings inside the container image, counting tokens offline with zero network calls.
  • Budget resolution: An explicit wahs.target_budget_tokens is clamped to fit inside WAHS_CONTEXT_WINDOW alongside system framing, conversation turns, and output reserve. In Auto mode, the engine uses WAHS_PREFERRED_CHART_TOKENS, falling back to the profile's preferred_chart_tokens or remaining window capacity. If multi-turn history still pushes total prompt tokens past the ceiling, assembler.py tightens the chart target and re-condenses before sending.
  • Truncation detection: upstream.py compares offline exact_prompt_tokens against upstream-reported prompt_tokens and sets suspected_upstream_truncation: true if the upstream count drops below 85% on prompts of 1,024+ tokens.
  • Fixed Ollama num_ctx: For litellm and ollama provider flavors, resolve_ollama_num_ctx pins requests at or below WAHS_OLLAMA_NUM_CTX (65536 in cloud) to a single warm bucket so changing UI budgets between 2k and 64k never triggers an Ollama model reload.

Sharing

SMART Health Links sharing

Summary sharing runs between the client browser and wahs-shl-server without touching wahs-engine. The client builds a FHIR R4 bundle from the user's selected items, encrypts it in the browser using WebCrypto compact JWE (alg: dir, enc: A256GCM, 32-byte random key), uploads the ciphertext to POST /shl/{id}/file, and encodes the manifest URL and decryption key into a shlink:/ link and QR code with an expiration date and optional passcode. Because the decryption key stays in the URL fragment, wahs-shl-server stores only ciphertext.
