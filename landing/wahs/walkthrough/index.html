WAHS Patient Chart Explorer Walkthrough

The WAHS Patient Chart Explorer has three steps: browse a multi-clinic FHIR R4 patient chart, condense it to a token budget between 256k and 1k, and run clinical tasks or questions against a connected model with citations that link back to the source records. The page URL records every setting, so a configuration can be bookmarked or shared.

Launch the live WAHS Explorer → Med Agent Hub architecture → WAHS project overview →

1 · Connect a model

Sign in to Cloud Med Agent Hub, or use your own model server

Steps 1 and 2 run in the browser without an account: all 10 patient charts, custom FHIR R4 bundle upload, and all 9 condensation budgets are available immediately. Step 3 generates summaries and answers questions, and requires a connected model.

Default connection: Cloud Med Agent Hub. No local installation is required.
  1. Open wahs-demo.openclinai.org.
  2. Open Settings (the gear icon in the top bar). Cloud Med Agent Hub is selected by default.
  3. Select Sign in with Google and sign in with an approved Google account.

To query the 13 models on the shared UW CIRG GPU server directly, without Med Agent Hub's knowledge base and clinical entity graph, select UW GPU Server in Settings. The same Google sign-in applies.

Use a local model server or OpenRouter

Settings can also point the explorer at a model server on your own workstation or at OpenRouter. With every backend, each model appears once in the model selector, and the + 4-Layer KB / Raw Chart Only toggle in the top bar selects the prompt variant.

The commands below are run from a checkout of the openclinai.org repository.

Local Med Agent Hub with llama-router (ports 18081 and 8077)

This option runs the full Med Agent Hub stack locally. Model files are downloaded on demand to ~/.cache/llama-router-models.

  • Start the router: ./scripts/llama-router-up.sh
  • Start Med Agent Hub: docker compose -f compose/openmrs-2.8-refapp.yml up -d med-agent-hub
  • In Settings, select Local Med Agent Hub (:18081), or open http://localhost:18081/wahs/demo.

LM Studio (port 1235 or 1234)

  • Start the server with CORS enabled, ~/.lmstudio/bin/lms server start --port 1235 --cors, and set the context length to at least 16384.
  • To reuse a model file that llama-router has already downloaded, import it without copying: ~/.lmstudio/bin/lms import -y -L --user-repo unsloth/gemma-4-12B-it-GGUF ~/.cache/llama-router-models/gemma-4-12b.gguf
  • In Settings, select LM Studio.

llama-router (port 8077), Ollama (port 11434), or OpenRouter

  • llama-router: run ./scripts/llama-router-up.sh and select llama-router (:8077) in Settings.
  • Ollama: run OLLAMA_ORIGINS="*" OLLAMA_CONTEXT_LENGTH=16384 ollama serve and select Ollama (:11434) in Settings.
  • OpenRouter: select OpenRouter in Settings, enter your sk-or-v1-... key in the API key field, and select Apply.
  • When the hosted page at https://wahs-demo.openclinai.org connects to a local port, Chrome and Brave require the Local network access site permission, available from the address bar.

3 · Guided experiments

Token budget, knowledge mode, and abstention

Each experiment requires a connected model (section 1). The expected results below were recorded with the default wahs-12b-kb profile (Gemma 4 12B).

Experiment 1 · Token budget

Compare an 8k budget with a 1k budget

Smaller budgets reduce prefill time at the cost of historical completeness. This experiment shows what the 1k budget removes from a 7,099-entry chart.

  1. In Step 1, select Maurice Auer (7,099 items).
  2. In Step 2, select 64k, 8k and 1k in turn and compare the condensed-chart bar in the context gauge with the 24k Recommended Limit marker of the default profile.
  3. With 8k selected, go to Step 3, keep Prepare My Next Doctor Visit Summary selected, and select Generate Live. Note the input token and line counts on the result card.
  4. Return to Step 2, select 1k, and generate again in Step 3.
Expected result: At 1k, the chart is reduced from 251,641 clinical tokens to about 902 tokens (15 lines). Over 2,400 items are trimmed, including 9 active conditions and 8 active medications. The trimmed-items panel in Step 2, and Advanced View in Step 3, list the omitted counts by category. Med Agent Hub uses these counts to decide whether to retrieve trimmed items on demand (Tier-0 overflow recovery).
Experiment 2 · Knowledge mode

Compare + 4-Layer KB with Raw Chart Only

This experiment shows how the deterministic clinical rules and the patient entity graph affect cross-clinic conflict detection with the same model.

  1. Select Elena Rostova (454 items) in Step 1 and 8k in Step 2.
  2. In Step 3, select the task Check Medication Conflicts, Duplicate Pills & Note Mismatches.
  3. With + 4-Layer KB selected in the top bar, select Generate Live.
  4. Switch the top-bar toggle to Raw Chart Only and generate again. Use Run History to switch between the two outputs.
Expected result: With Raw Chart Only, the model must identify, without assistance, that the hospital discharge summary instructed holding the outpatient spironolactone and potassium chloride orders because of a potassium result of 5.7 mmol/L. With + 4-Layer KB, the reconciliation finding and the connected clinical subgraph are included in the prompt. Citation numbers follow the current condensed chart, so they differ between budgets and modes.
Experiment 3 · Citations and abstention

Verify source citations and ask an unanswerable question

This experiment confirms that each clinical claim links to a FHIR resource, and that the model declines to answer when the chart does not contain the requested information.

  1. Continue with Elena Rostova and one of the outputs from Experiment 2. Select any [N] citation to open the source panel and compare the claim with the resource JSON.
  2. Select the question box in Step 3, type colonoscopy to filter the suggested questions, select Does this patient have a documented Penicillin allergy or recent colonoscopy?, and select Generate Live.
Expected result: Elena Rostova's chart contains no penicillin allergy and no colonoscopy. The response begins with an ABSTAIN: statement that the record was searched and no matching allergy or procedure exists. Arthur Pendelton and Lamar Beer do have colonoscopy entries, so the same question on those charts should be answered with citations.

4 · Reference and reports

Evaluated model families and published evidence

Each model profile in Med Agent Hub carries its maximum context window and its Recommended Limit (GET /v1/models?workflow=wahs). The explorer reads both values from the profile and shows them in the context gauge, so the current limits are always visible in the application. The top-bar toggle switches any model between + 4-Layer KB and Raw Chart Only.

Published evaluation reports

  • Huge-context (64k vs. 8k vs. 1k) and Med Agent Hub clinical entity subgraph evaluation → 32-cell comparison across MIMIC-IV-FHIR 2.0 and 53-year longitudinal cohorts measuring why Recommended Limit condensation + Hub ClinicalEntityGraph outperforms raw 64k context and recovers omitted clinical records at 1k.
  • 7-family profile benchmark with blinded dual-judge evaluation → 112-cell evaluation across Gemma 4, MedGemma, Qwen, Llama, Mistral, Granite and LFM2, comparing + 4-Layer KB with Raw Chart Only.
  • Local model screening and KB agent team evaluation → Three-stage screening of local models from 1.5B to 35B, and a four-arm comparison on lossless condensed charts without KB hints.
  • Condensation budget ablation and overflow chart retrieval → Where the 2k and 1k budgets trim history in multi-clinic FHIR R4 bundles, and how Tier-0 lookup tools recover recall.
