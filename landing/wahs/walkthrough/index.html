WA Health Summary (WAHS) · Walkthrough & Experimentation Guide

WAHS Patient Chart Explorer Walkthrough

The WAHS Patient Chart Explorer lets you inspect multi-clinic FHIR R4 patient charts in Step 1, condense them to a target token budget (256k down to 1k) in Step 2, and run live clinical tasks or custom questions with verifiable source citations in Step 3. Every setting can be bookmarked or shared directly via the page URL.

1 · Connect a Model

What works immediately and how to sign in for live generation

Steps 1 and 2 work without signing in: you can browse all 10 patient charts, upload a custom FHIR R4 bundle, and compare all 9 condensation budgets (256k to 1k) right away in the browser. Step 3 requires a model connection to generate clinical summaries and answer questions.

Default cloud setup (zero local installation):
  1. Open wahs-demo.openclinai.org.
  2. Click the ⚙️ button in the top bar (defaults to Cloud Med Agent Hub).
  3. Click Sign in with Google with a whitelisted @uw.edu or researcher account.

Direct UW GPU Server option: To query the 13 open-weight models on the shared UW CIRG GPU server directly—without Med Agent Hub’s knowledge-base and clinical entity graph orchestration—select UW GPU Server in the same ⚙️ modal. Your Google sign-in carries over automatically.

Run against your own local models or OpenRouter

In the ⚙️ modal, you can switch to a local server running on your workstation or to OpenRouter. Regardless of backend, each model appears once in the model selector and uses the main-app + 4-Layer KB vs. Raw Chart Only toggle.

Local Med Agent Hub + llama-router (ports 18081 and 8077)

Runs the full local Med Agent Hub stack with automatic on-demand GGUF downloads into ~/.cache/llama-router-models:

  • Start the router: ./scripts/llama-router-up.sh
  • Start Med Agent Hub: docker compose -f compose/openmrs-2.8-refapp.yml up -d med-agent-hub
  • In ⚙️, select Local Med Agent Hub (:18081) (or open http://localhost:18081/wahs/demo).

LM Studio (port 1235 or 1234)

  • Start the server with CORS enabled: ~/.lmstudio/bin/lms server start --port 1235 --cors and set Context Length to at least 16384.
  • Optional zero-copy import of an existing GGUF: ~/.lmstudio/bin/lms import -y -L --user-repo unsloth/gemma-4-12B-it-GGUF ~/.cache/llama-router-models/gemma-4-12b.gguf
  • In ⚙️, select LM Studio.

Direct llama-router (port 8077), Ollama (port 11434), or OpenRouter

  • llama-router: Run ./scripts/llama-router-up.sh and select llama-router (:8077) in ⚙️.
  • Ollama: Run OLLAMA_ORIGINS="*" OLLAMA_CONTEXT_LENGTH=16384 ollama serve and select Ollama (:11434) in ⚙️.
  • OpenRouter: Select OpenRouter in ⚙️, paste your sk-or-v1-... key into the API key field that appears, and click Apply.
  • Browser localhost permission tip: If connecting from https://wahs-demo.openclinai.org to a local port in Chrome or Brave, allow Local network access in the address-bar site permissions.

3 · Hands-On Recipes

Three quick experiments to try on wahs-demo.openclinai.org

Recipe 1 · Token Budget Comparison

Compare a 64k or 8k chart against a 1k micro-budget

See how aggressive token budgets trade off historical completeness for faster prefill on a 7,099-entry longitudinal chart.

  1. In Step 1, select Maurice Auer (7,099 items).
  2. In Step 2, click through 64k, 8k, and 1k while watching the context gauge bar shrink against the fixed 24k Recommended Limit marker.
  3. At 8k, go to Step 3, keep Prepare My Next Doctor Visit Summary selected, and click Generate Live. Note the input token and line counts on the result card.
  4. Return to Step 2, switch to 1k, and click Generate Live again in Step 3.
What to look for: At 1k, Maurice Auer’s chart is compressed from 251,641 clinical tokens to ~902 tokens (15 lines), trimming over 2,400 items—including 9 active conditions and 8 active medications that exceed the 1,024-token ceiling. Expand the trimmed-items panel in Step 2 (or Advanced View in Step 3) to see the exact omitted counts, which Med Agent Hub uses to trigger on-demand Tier-0 overflow recovery.
Recipe 2 · Knowledge Mode Comparison

Compare + 4-Layer KB against Raw Chart Only

Test how deterministic clinical rules and the patient entity graph affect cross-clinic conflict detection on the same model.

  1. Select Elena Rostova (454 items) in Step 1 and 8k in Step 2.
  2. In Step 3, open the task dropdown and select Check Medication Conflicts, Duplicate Pills & Note Mismatches.
  3. With + 4-Layer KB active in the top bar, click Generate Live.
  4. Switch the top-bar toggle to Raw Chart Only and click Generate Live again, then use Run History to compare both runs side by side.
What to look for: Under Raw Chart Only, the model must spot on its own that the hospital discharge note [19] instructed holding outpatient spironolactone [8] and potassium chloride [9] due to potassium 5.7 mmol/L [25]. Under + 4-Layer KB, the structured reconciliation finding and connected clinical subgraph are supplied directly in the prompt.
Recipe 3 · Citations & Safety Abstention

Verify source citations and test an unanswerable question

Confirm that every clinical claim links to a real FHIR resource and that the model abstains when asked about unrecorded history.

  1. In Step 3, click any blue [N] citation badge in a generated summary to open the slide-over FHIR R4 source drawer and verify the underlying resource JSON.
  2. Click the custom question box in Step 3 to open the suggested prompts, type colonoscopy to filter the list, select the colonoscopy question, and click Generate Live.
What to look for: Because the chart contains no colonoscopy report or genetic testing record, the response begins with an explicit ABSTAIN: statement confirming that the record was searched and no matching procedure exists, rather than guessing.
