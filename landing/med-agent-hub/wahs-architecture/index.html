Med Agent Hub · WAHS+ Clinical Context & Orchestration Architecture

Patient Clinical Entity Graph, Progressive FHIR Condensation & Pre-Generation Intelligence.

Med Agent Hub powers the Washington Health Summary (WAHS+) workstream by transforming raw, fragmented multi-clinic FHIR R4 exports (up to 18.8 MB and 115,000+ tokens) into provenance-linked clinical ledgers, deterministic chart-hygiene skill findings, and pre-generation context enrichment blocks for open-weight clinical models.

Section 1 · System Boundary & Division of Responsibility

How WAHS+ and Med Agent Hub work together

Rather than passing raw FHIR JSON directly to a language model or relying on opaque lossy summarization, Med Agent Hub separates deterministic clinical parsing, non-destructive structural condensation, pre-generation knowledge-base graph linking, and bounded LLM synthesis.

Layer 1 · Ingestion & Normalization

Lossless FHIR R4 Extractor

server/fhir/extractors.py parses US Core, HL7 IPS, and multi-clinic FHIR R4 Bundles, resolving internal references, inverting Provenance.target[] into per-resource facility tags, deduplicating Base64 clinical notes, and normalizing RxNorm, SNOMED CT, LOINC, and CVX codes.

Layer 2 · Non-Destructive Condensation

7-Budget Structural Condenser

server/fhir/condenser.py compiles numbered clinical ledger lines ([1] ... [N]) across 64k, 32k, 16k, 8k, 4k, 2k, and 1k token budgets while emitting a machine-readable Completeness Manifest that tracks exact omitted_clinical_items counts.

Layer 3 · Pre-Generation Intelligence

Clinical Entity Graph & Overflow Recovery

server/fhir/clinical_graph.py constructs a patient-specific ClinicalEntityGraph, executes question-conditioned 4-layer KB lookup, and conditionally triggers Tier-0 overflow recovery via wahs_tools.py only when the active budget omitted clinical items.

Layer 4 · Profile Execution

OpenAI-Compatible WAHS Profiles

server/openai_compat.py serves workflow: wahs profiles (wahs-*-kb vs. wahs-*-raw) over local llama-router and cloud OpenRouter endpoints, attaching hub_enrichment telemetry in both JSON responses and SSE streams.

Section 2 · Progressive FHIR Condensation & Completeness Manifest

From 100k-token FHIR JSON to verifiable numbered ledgers (64k down to 1k)

Every condensed chart starts with patient demographics at [1] and a deterministic Completeness Manifest at [2]. Because structural condensation strips transport wrapper noise first, budgets from 64k down to 4k typically retain 100% of clinical items (omitted_clinical_items=0), whereas tight 2k and 1k budgets prioritize the HL7 IPS Safety Core (allergies, active problems, active medications, and recent key labs) and record any overflow omissions explicitly.

Budget Window Condensation Strategy Typical Omitted Clinical Items Tier-0 Overflow Recovery Behavior
64k / 32k / 16k Full lossless structural condensation with complete longitudinal lab timelines, encounter histories, and decoded narrative notes. omitted_clinical_items = 0 (100% clinical coverage) Skipped (overflow_triggered: false) — prevents duplicate context bloat when all clinical items are already in the prompt.
8k / 4k Compact longitudinal rollups preserving active conditions, active medications, allergies, immunizations, and priority lab trajectories. omitted_clinical_items = 0 on standard charts; non-zero only on massive 7,000-entry exports. Conditional — runs only if omitted_clinical_items > 0 in the Completeness Manifest.
2k / 1k Strict HL7 IPS Safety Core budget; older narrative clinical notes and secondary lab panels overflow the token ceiling. omitted_clinical_items > 0 (e.g., clinical_note, lab_observation) Active (overflow_triggered: true) — wahs_tools recover question-relevant Tier-0 notes and lab series with sequential [N] citations.

Section 3 · Deterministic Pre-Generation Context Intelligence

Inside build_wahs_hub_enrichment_block(...)

When a request executes against any KB-guided WAHS profile (include_kb_findings: true, such as wahs-12b-kb, wahs-e4b-kb, or wahs-26b-kb), Med Agent Hub runs four deterministic pre-generation stages before invoking the language model and injects a bounded (≤ 800 token) orchestration block at the end of the user prompt.

Rule 1 · Conditional Tier-0 Overflow Recovery

Targeted Retrieval Only When Needed

The Hub parses omitted_clinical_items and budget_overflow_omitted from the prompt’s Completeness Manifest. When omitted_clinical_items == 0, overflow retrieval is bypassed completely. When omitted_clinical_items > 0, the Hub invokes read_clinical_note, get_lab_history, and search_chart_entries against the uncondensed ExtractedChart and assigns sequential [max_citation_idx + 1] tags with [UUID: <resource_uuid>] provenance.

Rule 2 · Patient Clinical Entity Subgraph

ClinicalEntityGraph Multi-Hop Linking

ClinicalEntityGraph links 7 node categories (Condition, MedicationRequest, Observation, DocumentReference, AllergyIntolerance, Immunization, and Organization) across 5 typed clinical edges while preserving original [N] citation indices so small and mid-size models do not have to infer multi-hop cardiorenal or anticoagulation interactions from raw text alone.

Rule 3 · Question-Conditioned 4-Layer KB

Live Clinical Guideline & Code Lookup

The Hub extracts clinical terms from the active USER_QUESTION alongside SNOMED CT, ICD-10, LOINC, RxNorm, and CVX codes in the chart and queries server.kb.search(query=..., corpus="wahs", k=4) across KDIGO CKD staging, AHA/ACC/HFSA heart failure GDMT, CHEST/FDA anticoagulation rules, CDC ACIP immunization schedules, and 42 CFR Part 2 / WA MHMDA privacy rules.

Graph Edge Type Source → Target Nodes Clinical Logic & Knowledge Base Grounding
TREATS MedicationRequest → Condition Maps active medications to documented clinical indications via RxNorm class/indication lookup and AHA/ACC/ADA/KDIGO therapeutic mappings (e.g., Apixaban [6] --[TREATS]--> Atrial fibrillation [5]).
CONTRAINDICATED_OR_DOSE_ADJUST_IN MedicationRequest → Condition / Observation / AllergyIntolerance Flags renal dosing thresholds, hyperkalemia hazards, supratherapeutic INR, NSAID nephrotoxicity/bleeding, and allergy cross-reactivity (e.g., Spironolactone [7] --[CONTRAINDICATED_OR_DOSE_ADJUST_IN]--> Potassium 5.6 mEq/L [10]).
MONITORED_BY Condition / MedicationRequest → Observation Connects chronic diseases and high-alert therapies to their longitudinal LOINC laboratory and vital trajectories (eGFR, Creatinine, Potassium, HbA1c, INR, NT-proBNP, LDL-C, TSH).
CONTRADICTED_OR_MODIFIED_BY_NOTE MedicationRequest / Condition → DocumentReference Detects narrative-vs-structured discrepancies where a clinical note documents self-discontinuation, dose reduction, walk-in urgent care changes, or disease stage progression.
REPORTED_BY_ORG Clinical Node → Organization Preserves multi-facility care provenance (e.g., primary health system vs. outside walk-in urgent care or external reference laboratory).

Section 4 · Dual-Provider Model Routing & Telemetry

Comparing -kb vs. -raw across local and cloud open-weight models

Med Agent Hub exposes paired WAHS profiles in levels.yaml so researchers and clinicians can perform controlled ablations isolating the effect of Hub pre-generation intelligence across model sizes (`2B` to `35B`) and providers (local `llama-router` on Apple Silicon / UW CIRG H200 GPUs vs. cloud OpenRouter).

KB-Guided Profiles (wahs-*-kb)

Full Hub Pre-Generation Enrichment

Profiles with include_kb_findings: true (e.g., wahs-12b-kb, wahs-e4b-kb, wahs-medgemma-27b-kb, wahs-26b-kb) combine the clinical reconciliation system prompt with the bounded ≤ 800-token orchestration block and return structured telemetry in body["hub_enrichment"], the first SSE chunk, and the X-WAHS-Hub-Enrichment HTTP header.

Raw Unhinted Profiles (wahs-*-raw)

Zero-Hint Baseline Ablation

Profiles with include_kb_findings: false (e.g., wahs-12b-raw, wahs-e4b-raw, wahs-26b-raw) pass the condensed chart ledger and user question directly to the model with an unhinted baseline prompt and no orchestration injection, providing a clean scientific control across all 7 token budgets.
