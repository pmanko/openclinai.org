## On the running stack

The owner's stack (`harness-*`) ran the 18 October builds. Its database was
backed up, the three modules and the frontend were rebuilt from the tips, and the
stack was restarted.

- **Module upgrade from the 18 October database.** OpenMRS started; changeset 011
  was marked ran (that database never had the title column); every QueryStore type
  was `COMPLETED` about 20 seconds after startup.
- **Both providers, five questions each** (`scripts/time-chart-questions.py`,
  sample HIV chart, `eval-nurse`): built-in 13–55 s, Hub 114–150 s, with the same
  facts (weight 71 kg, nevirapine, lamivudine and stavudine, CD4 341 with no viral
  load, no recorded drug allergies). All ten turns ended `turn_done` with an audit
  row; Hub rows record search mode `unknown`.
- **Privilege filter** (#85). A user holding only Get Patients read one record of
  the sample chart (the patient) where the administrator reads 365, and none of
  the 20 cross-patient hits for "viral load".
- **Restart top-up skip** (new PR). A record the bootstrap had written was skipped
  on the next restart (`obs` `documents_indexed` unchanged). A record written by
  steady-state sync was not, because sync stored it without `last_modified`: the
  save event publishes before the save stamps its audit dates. Fixed on the branch
  (`91c17e1`: the after-commit write reads the version off the committed entity;
  `35df0c9`: versions compare to the second). After the rebuild a sync-written obs
  carried its version and the next restart skipped it.
- **Chart-search UI.** The Hub answered a medication question with a checked
  answer, In-Depth, a medication table and six verified citations, and a "Limited
  safety check" box naming the research reference sources. Switching provider
  started a new conversation; the built-in provider answered and its conversation
  was restored after a page reload. With the Hub container stopped, picking the Hub
  showed "AI profiles are unavailable. Check the med-agent-hub connection." and the
  Hub recovered when restarted.
- Test data added for these checks (three weight obs, one test user) was voided
  or retired afterwards; sync removed the voided obs from the index.

## Findings

- The sync-written version gap above, fixed on `codex/bootstrap-skip-unchanged`.
- Same-day readings have no order: QueryStore record dates are day-granular, so
  three weights recorded on one day were answered with the first by uuid, not the
  last. Existing behaviour, not introduced here.
- Built-in streaming answers report 0/0 tokens, so their audit rows now record
  null, as `/search` already does.
- The Hub provider reports ready while its container is stopped; the failure
  surfaces at profile discovery instead.
